# #skills 區塊資訊架構與視覺設計

## Context

`#skills`（技能區塊）目前分「技術／工具／語言」三個子群組，每個項目只有 `skills__name` + `skills__level`（自由文字，如「熟練度佔位」）兩個欄位，且 `_skills.scss` 幾乎是空檔案（只有一行註解），編譯後的 `main.css` 查無任何 `.skills` 規則——這個區塊完全沒有視覺樣式，跟全站其他區塊（`#about`、`#resume`）已經確立的深空藍／磚紅／Space Mono 等寬字語彙完全脫節。

用 `/adversarial-ux-test` 模擬一位每天要看 40–50 份新鮮人履歷網站的挑剔 HR（persona：陳姐）檢視後，找出兩個真實問題：
1. **視覺斷層（RED）**：`#skills` 沒有樣式，觀感上像「沒做完」，拖累整體專業度印象。
2. **自評形容詞不可信（GREEN，內容架構問題）**：「熟練度佔位」這種自由文字自評（熟練/精通）沒有量化或佐證，任何看多了履歷的人都會打折扣。

因此用 `/brainstorming` 搭配瀏覽器視覺化輔助，逐步釐清「熟練度」要怎麼呈現才能兼顧誠實感、視覺一致性、資訊密度，並確認 `#skills` 與 `#resume` 專案標籤的分工關係，最終收斂出以下設計。

## 內容架構：必要資訊 vs. 完整擴充資訊

### 必要資訊（每個技能項目都要有）

| 欄位 | 說明 |
|---|---|
| 技能名稱 | 沿用現有 `skills__name`，視覺上比照 `about__tag` / `resume__project-tag` 的「# 標籤」等寬字語彙 |
| 分類 | 沿用現有三分類：技術／工具／語言 |
| 熟練度等級 | **技術／工具**：比照 CEFR 歐洲語言框架的六級劃分（入門/基礎/中等/中高/高等/精通），用 6 顆圓點呈現，因為這兩類沒有官方檢定可佐證，套用一個公認、非隨意發明的分級框架，比純形容詞自評更有可信度。**語言**：不套用 CEFR 圓點，改成直接顯示真實檢定名稱＋級別＋取得年份（例如「JLPT N3・2024 年取得」），因為語言能力本來就有公認的外部檢定（JLPT/TOEIC/CEFR 等），比自訂量表更誠實、更具體。 |

### 完整擴充資訊（可選，資料齊全時才顯示，不齊全就顯示替代文字，不留空白區塊）

| 欄位 | 說明 |
|---|---|
| 接觸時長（年資） | 技術／工具類專用；用一條「65 年尺標」的長條呈現（100% 寬度＝65 年），刻意讓 3–5 年這種正常年資只填色 3–8% 左右，長條本身退居成背景刻度感，**實際數字（如「3 年」）才是主要可讀資訊**，避免長條長短被誤讀成「技術強弱」。畫面上不顯示尺標倍率文字，只當內部換算比例。 |
| 檢定取得時間 | 語言類專用，取代年資列，文字寫法直接沿用 `#resume` 已經確立的 `.resume__cert-meta`「頒發單位・取得時間」語彙（例如「JLPT N3・2024 年取得」），沒有官方檢定時退回寫「自學・日常對話程度」這類描述，不強制造假數據。 |
| 佐證作品連結 | 標示這個技能實際用在哪些 `#portfolio` 作品上。平常只顯示「用於 N 個作品 ▾」一行（點擊才展開），避免固定佔用大量垂直空間；展開後用 **6 欄網格**排列連結（桌面），手機窄螢幕降到 3–4 欄，連結文字過長時用 ellipsis 截斷；沒有對應作品時顯示「尚無對應作品連結」，語言類技能則不強制附作品佐證。 |

## 如何展現特色

1. **延續既有視覺語彙，不另創一套系統**：技能標籤沿用 `about__tag`/`resume__project-tag` 的「# + Space Mono 等寬字」樣式；語言檢定文字沿用 `resume__cert-meta` 的「名稱・時間」寫法；連結底線沿用全站慣用的 dashed underline（呼應 `resume__pdf-link` 外框、`about__motto` 分隔線等磚紅系裝飾）。這樣 `#skills` 補上樣式後會立刻融入全站設計識別，而不是自成一格。
2. **用「誠實感」取代「灌水感」作為差異化賣點**：65 年尺標刻意讓年資長條看起來「謙虛」、CEFR 六級量表是外部公認框架而非自吹自擂的形容詞、語言檢定直接秀出真實考試名稱與年份——整體策略是讓 `#skills` 讀起來像「有根據的紀錄」而非「自我行銷文案」，這對照 adversarial test 裡陳姐「不信形容詞、只信證據」的訴求。
3. **`#skills` 與 `#resume` 明確分工，不重複但互相佐證**：`#skills` 是完整技能庫（涵蓋所有接觸過的技術/工具/語言），`#resume` 專案標籤是「這個專案實際用了什麼」的子集標記；`#skills` 的「用於 N 個作品」連結回頭指向 `#portfolio`／`#resume` 的具體專案，讓兩個區塊變成「總覽 ↔ 實例」的雙向佐證關係，而不是各自獨立、內容重複的兩份清單。

## 排版明細（供實作參考）

- 每個技能項目分兩行：**第一行**＝技能標籤（左）＋熟練度指標（右，技術/工具用 6 點量表+等級文字，語言只有標籤沒有這行右側內容）；**第二行**＝技術/工具顯示「年資數字＋65年尺標長條」，語言改顯示「檢定名稱・取得年份」文字（比照 `.resume__cert-meta`）。
- 第三行（可選）＝佐證作品：預設收合成「用於 N 個作品 ▾」一行文字＋徽章式數字，點擊展開一個 6 欄網格清單；沒有作品時顯示灰階提示文字「尚無對應作品連結」，語言類不顯示這行或改用更簡短的字樣。
- 整體字級比目前 `_skills.scss`（目前完全無自訂樣式、吃瀏覽器預設）明顯放大，實際 rem 數值待實作階段依全站 body 字級比例套用（本站目前無中央字體變數，需逐一手動設定，比照 `_about.scss`/`_resume.scss` 的既有做法）。
- RWD：6 欄網格在窄螢幕（例如 <600px）降為 3–4 欄，避免連結文字被壓得只剩省略號。

## 尚未決定 / 實作階段需要的資訊

- CEFR 六級對應到「技術/工具」熟練度的實際判斷標準（例如什麼條件算「中高」）由使用者自行填寫真實資料時決定，這份設計只定架構不代填內容。
- 65 年尺標、6 欄網格等數值是設計階段的具體決策，實作時如需依實際內容微調（例如作品數量特別多或特別少時的視覺效果），仍應維持本文件的方向（誠實感優先、避免重複、資訊分層收合）。

## 本次分析範疇

這份文件只是資訊架構與視覺設計的規格，**尚未動任何程式碼**（`_skills.scss` 目前仍是空的，`index.html` 的 `#skills` 結構也還是原本的佔位版本）。是否要接著進入實作（改 HTML 結構 + 寫 CSS），需要使用者確認後才進行。
