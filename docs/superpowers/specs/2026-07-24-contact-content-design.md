# #contact（聯絡方式）內容架構規劃

## 現況

`#contact` 是全站九大區塊中最後一個還沒被認真規劃過的區塊：只有一句 Email（真實資料）、GitHub/LinkedIn 兩個佔位社群連結、以及一份完全沒有 `action`/後端的聯絡表單骨架（姓名/Email/訊息/送出鈕，按下送出目前什麼都不會發生，這是 2026-07-20 建立時就刻意的決定，見 `claude_core_assistant.md` 第 9 筆：「聯絡表單這次只搭骨架、不串接，因為串接方式屬於之後才會定案的技術細節」）。`_contact.scss` 完全空白，標題也還停留在只調字級（2rem）、沒有 eyebrow 樣式的階段。

## 已確認方向

用 AskUserQuestion 分三輪確認：

1. **聯絡表單最終處理方式**：改用 `mailto:` 表單提交（不接第三方表單服務，不移除表單）。
2. **要不要補求職/合作意向 CTA、回覆時間/聯絡偏好說明**：都要。
3. **候選新增聯絡方式**：追加 Discord/LINE ID、Instagram（IG）；履歷 PDF 下載連結、QR Code 名片這輪不加，記錄為 Tier 2 候選。

## 內容架構：必要資訊 vs. 補充資訊

### 必要資訊

| 欄位 | 說明 | 現況 |
|---|---|---|
| Email | mailto 連結 | 已有（真實資料） |
| 社群/外部連結清單 | GitHub／LinkedIn／Discord 或 LINE／Instagram 四項 | GitHub/LinkedIn 已有（佔位），Discord/LINE、Instagram 為新增 |
| 聯絡表單 | 姓名／Email／訊息／送出，改用 `mailto:` 提交 | 需要補上真正的提交機制 |

### 補充資訊

#### Tier 1：這輪確認要加

| 欄位 | 說明 | 理由 |
|---|---|---|
| 求職/合作意向 CTA | 一句話說明目前想找什麼機會 | 呼應 `#goals` 短期目標的動機，寫成對外的明確呼籲，比「歡迎聯絡」更具體，提高被聯繫的機率 |
| 回覆時間/聯絡偏好說明 | 例如「Email 是最快找到我的方式，通常 3 天內回覆」 | 幫聯絡者判斷該用哪個管道、設定合理期待 |

#### Tier 2：這輪不加，記錄候選但不落地

| 欄位 | 說明 |
|---|---|
| 履歷 PDF 下載連結 | 呼應 `#resume`，之後有實際 PDF 素材時再加 |
| QR Code 名片 | 適合實體徵才博覽會/黑客松場合，之後真的需要再做 |

## Governance 決策

1. 社群連結清單擴充到 4 個平台後，規模跟 `#activities`/`#skills` 的清單相近，是否納入 JSON + 建置腳本範圍列入技術選型清單。
2. Discord/LINE 沒有像 GitHub/LinkedIn 那樣乾淨的個人頁面網址，呈現方式（純文字 ID vs 深連結）列入技術選型清單。
3. `mailto:` 表單提交有兩種做法（純 HTML `action="mailto:"` vs 加小段 JS 組出 mailto 連結），是本輪最大的技術決策，列入技術選型清單。

## 如何展現特色

- 求職/合作意向 CTA 用具體語句而非空泛的「歡迎聯絡」，呼應全站「誠實感優先」的內容設計原則，也讓 `#goals`（動機）與 `#contact`（明確呼籲）兩個區塊首尾呼應。
- 回覆時間/聯絡偏好說明是全站目前沒有的「使用者體驗提示」類型內容，用一句話管理聯絡者的期待。

## 技術選型清單：確認結果

1. **`mailto:` 表單要不要額外加一小段 JS** → **加**。送出時用 JS 組出 `mailto:` 連結再導頁，比純 HTML `action="mailto:"` 更可靠。`#contact` 會是全站第二個用到自訂 JS 的區塊（第一個是 `filter.js`）。
2. **社群連結清單要不要納入 JSON + 建置腳本範圍** → **要**。比照 `#activities`/`#skills` 的 group/list 模式。
3. **社群連結圖示要怎麼處理** → **改用 inline SVG 品牌標誌**（不是文字連結、也不是 Google Material Symbols 通用圖示——Material Symbols 沒有品牌專屬圖示，只有通用 UI 符號，不適合用來代表 GitHub/LinkedIn 等平台）。GitHub／LinkedIn／Discord 或 LINE／Instagram 各自用可辨識的品牌 SVG，不需要外部 CDN/字型依賴，檔案小且顯示穩定。
4. **標題要不要一併升級成 eyebrow 樣式** → **可以**，追上其他區塊的進度。

## 排版方向：確認結果

排版方向前後經過兩輪迭代：

1. 第一輪給了「單欄堆疊」與「左右兩欄（呼應 `#about__layout`）」兩款通用骨架，使用者認為「缺乏創新」。
2. 第二輪改給 4 款各自有明確論述、且都重組全站既有語彙的方向：
   - A. 終端機提示列：CTA 寫成一行指令，尾端接 header 同款閃爍游標，維持全站淺色調性（不做深底面板）
   - B. Email 簽名檔式收尾：整段做成「如果現在寄信給你，簽名檔會長這樣」的樣子
   - C. 狀態列：沿用 `#goals`/`#skills` 的圓點語彙，做成會脈動的「即時求職狀態」窄條
   - D. 回音式對話預覽：用「你/我」兩行極簡對白，把聯絡方式框成「即將發生的對話」

**確認採用方向 A（終端機提示列）**：CTA（求職/合作意向）用一行 `contact --intent` 提示列呈現，尾端接閃爍游標（沿用 header 已有的 blink 動畫，不新增顏色/視覺系統），下方接聯絡偏好說明、Email、社群 SVG 圖示列、mailto 表單。
